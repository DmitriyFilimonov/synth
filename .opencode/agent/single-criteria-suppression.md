## Краткое содержание изменений итерации

1. **Баг репоринга итераций**: последний `emitProgress` в `coordinateDescent` писал `maxIterations` (прошено 3000) вместо фактического `iter` (~270) — UI показывал 3000 хотя выполнилось ~270. Исправлено: `emitProgress(history, onProgress, iter, currentBest, lastCycleLabel)`.
2. **Добавлен итоговый лог**: `console.log` после всех циклов показывает фактическое число итераций и количество завершённых циклов.
3. **CRIT-3 (suppression)**: плато стабильно ~24–33% на честной метрике (windowed fixed scale 1). До 98% далеко — это 4-й цикл подряд с WARN по CRIT-3. Гипотезы: (a) фаза (phaseStepPrecision 0.0002 ≈ 0.07° может быть недостаточно для Δφ ≤ 1.15°); (b) начальный масштаб (init vol 0.1 vs target 0.5 — CD не дотягивает за 300–600 итер); (c) честная метрика без свободного масштаба принципиально строже.

## Критерий (CRIT-3)
Целевая метрика: suppressionPercent ≥ 98%; текущий результат не деградирует ниже задокументированного плато (~50%)

## Как проверять
- Проверь актуальные результаты suppressionPercent: запускал ли проект недавно матчинг? Есть ли логи/результаты?
- Проверь, что метрика suppressionPercent считается корректно (RMS-based, src/cancellation-assessment.ts, src/optimize/evaluate.ts).
- Сверь с предыдущими отчётами в .opencode/criteria/state/ (если есть) — есть ли деградация ниже ~50%?
- Текущее плато ~24-33% (по данным итерации) — это ниже documented ~50%, что является признаком деградации.
- Ключевые файлы: `src/optimize/evaluate.ts`, `src/cancellation-assessment.ts`, `src/rms.ts`, `.opencode/criteria/state/`.

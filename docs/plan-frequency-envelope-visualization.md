# План реализации: визуализация огибающих частоты

**Статус:** декомпозиция утверждена к использованию; реализация не
начата.

Нормативный источник требований —
[`spec-frequency-envelope-visualization.md`](spec-frequency-envelope-visualization.md).
Этот документ определяет только порядок работ, границы задач и состав
контекста. При расхождении со спецификацией приоритет имеет
спецификация; менять её в ходе задач без согласования нельзя.

## 1. Правила выполнения

1. Основной порядок: **T1 → T2 → T3 → T4 → T5**. Задачи выполняются
   последовательно, чтобы не создавать конфликты в общих файлах.
2. Каждую задачу рекомендуется выполнять в новой сессии. Нужно
   прочитать только её карточку, указанные разделы спецификации и
   перечисленные файлы; широкое исследование репозитория не требуется.
3. В T1–T4 **запрещены запуски тестов, lint, сборок и smoke-тестов**.
   Единственный комплекс проверок выполняется в T5 после завершения
   всех правок.
4. Не изменять оптимизатор, вычисления синтеза, контракт patch/job,
   `visualize.ts`, `visualize-envelopes.ts` и существующие
   match-визуализации.
5. Не расширять задачу соседней функциональностью. Обнаруженный
   блокер вне разрешённых файлов нужно зафиксировать в журнале и
   согласовать, а не обходить широким рефакторингом.
6. После каждой задачи обновить её статус и краткий журнал в конце
   этого документа. В журнале указать изменённые файлы, отклонения и
   информацию, необходимую следующей задаче.
7. Для новой сессии достаточно prompt: «Выполни задачу TN из
   `docs/plan-frequency-envelope-visualization.md`. Соблюдай границы
   контекста и файлов из карточки; проверки не запускай». Для T5
   последняя фраза заменяется на «Выполни один финальный комплекс».

## 2. T1. Независимый SVG-модуль

**Цель:** получить чистый модуль `ArgCreateSynth` → SVG-строка и
написанные, но ещё не запущенные unit-тесты.

**Спецификация:** разделы 3–5; критерии 1–3 из раздела 10.

**Прочитать:**

- `src/synth.ts`;
- `src/envelope.ts`;
- `src/consts.ts`;
- `src/presets.ts` — только как источник примера конфигурации;
- `package.json` — текущие scripts и наличие `tsx`.

**Изменить:**

- `src/synth.ts` — только экспорт существующей frequency-функции;
- новые файлы `src/frequency-envelope-visualization/index.ts`,
  `types.ts`, `render-frequency-envelopes.ts`,
  `render-frequency-envelopes.test.ts`;
- `package.json` — команда `test` через Node test runner и `tsx`;
- статус/журнал этого плана.

**Шаги:**

1. Экспортировать существующую функцию частотной огибающей, не меняя
   её вычисления или поведение `createSynth`.
2. Определить публичные типы и функцию
   `renderFrequencyEnvelopesSvg()` с контрактом из спецификации.
3. Реализовать проверку patch, выбор активных осцилляторов и ошибки
   входных данных.
4. Реализовать детерминированный SVG с общими осями, легендой и
   стабильной привязкой цвета к исходному индексу.
5. Добавить тесты формулы, clamp, выбора, ошибок и повторяемости SVG.
6. Настроить `npm test` без новых зависимостей. Не запускать его.

**Граница результата:** API и UI отсутствуют; модуль можно вызвать
напрямую из TypeScript-кода.

**Definition of Done без запуска проверок:**

- публичная сигнатура соответствует спецификации;
- модуль не импортирует Express, API, `fs`, DOM или React;
- формула синтезатора не продублирована;
- default/explicit selection и все ошибки выбора реализованы;
- тесты покрывают заявленные случаи;
- никакие проверки не запускались.

**Изменить:**

  `ui` и публичным `index.ts`;

- `web/src/app/App.module.css`, только если существующих стилей
  недостаточно;
- статус/журнал этого плана.

**Шаги:**

1. Добавить типы patch и API-функцию POST, возвращающую SVG Blob.
2. Реализовать чтение и разбор `.json`, отображение ошибок и имени

**Definition of Done без запуска проверок:**

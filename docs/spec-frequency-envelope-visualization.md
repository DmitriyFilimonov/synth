# Спецификация: визуализация огибающих частоты

**Статус:** реализована; финальный комплекс проверок T5 успешно
завершён.

**План реализации:**
[`plan-frequency-envelope-visualization.md`](plan-frequency-envelope-visualization.md).
Спецификация остаётся источником требований; план определяет порядок
задач, их зависимости и минимально необходимый контекст.

Документ фиксирует поведение независимого модуля генерации SVG, его
интеграции с Web API и пользовательского интерфейса. Фактические
результаты реализации и проверок приведены в плане.

## 1. Контекст

Существующий `src/visualize-envelopes.ts` строит графики амплитуды и
частоты только для первого осциллятора тестового пресета. Используемый
им `plotToSvg()` из `src/visualize.ts` напрямую записывает результат в
файл и поэтому не подходит как независимый генератор SVG для Web API.

Выходной патч мэтчинга имеет формат `ArgCreateSynth` и уже доступен в
`job.synthConfig`. Пользователь также может получить его через
`/api/match/jobs/:id/download-params`.

## 2. Цель

Добавить возможность:

- визуализировать огибающие частоты из `synthConfig` завершённого
  задания мэтчинга;
- загружать произвольный JSON-патч формата `ArgCreateSynth`;
- выбирать осцилляторы, огибающие которых нужно показать;
- просматривать результат в браузере и скачивать его как SVG;
- использовать генератор SVG независимо от Web API.

Оптимизация при визуализации не перезапускается. Существующие WAV,
JSON и алгоритмы синтеза не изменяются.

## 3. Независимый модуль

Целевое расположение:

```text
src/frequency-envelope-visualization/
├── index.ts
├── types.ts
├── render-frequency-envelopes.ts
└── render-frequency-envelopes.test.ts
```

Публичный интерфейс:

```ts
renderFrequencyEnvelopesSvg(
  patch: ArgCreateSynth,
  options?: {
    oscillatorIndices?: readonly number[];
  },
): string;
```

Требования к модулю:

- принимает патч и возвращает SVG-строку;
- не импортирует Express, API, `fs`, DOM или React;
- ничего не записывает на диск;
- не выполняет синтез WAV;
- не имеет внешних runtime-зависимостей;
- может использоваться Web API, CLI или другим потребителем;
- использует существующую математическую функцию частотной огибающей
  из `synth.ts`, не дублируя формулу.

Это отдельный архитектурный модуль внутри репозитория, но не отдельный
npm-пакет.

## 4. Выбор осцилляторов

`oscillatorIndices` содержит нулевые индексы элементов исходного
`patch.oscillators`.

- Если параметр не передан, визуализируются все осцилляторы с
  `osc.on === true`.
- Если параметр передан, визуализируются только выбранные активные
  осцилляторы.
- Порядок кривых соответствует их порядку в патче, а не порядку
  индексов в запросе.
- Выключенные осцилляторы не участвуют в визуализации.
- Пустой выбор, отсутствующие индексы и выбор выключенных
  осцилляторов считаются ошибкой входных данных.
- В SVG и интерфейсе сохраняются исходные номера: `OSC 01`, `OSC 02`
  и т.д.

## 5. Математика и SVG

Для осциллятора используется текущая формула синтезатора:

```text
f(t) = freqBase
     + (freqStart - freqBase)
     × exp(ln(0.001) × (clamp(t, 0, duration) / duration)^slope)
```

На `t = duration` нормированная огибающая равна `0.001`, поэтому
значение частоты не обязано совпадать с `freqBase` абсолютно точно.
При `t > duration` сохраняется финальное значение.

Один SVG содержит общий график выбранных кривых:

- ось X — время от `0` до `0.5` секунды;
- ось Y — частота в герцах, логарифмическая шкала с автоматическим
  диапазоном; равные отношения частот занимают равные вертикальные
  интервалы, чтобы низкие частоты оставались различимыми;
- сетка, подписи осей и числовые деления;
- отдельная кривая и цвет для каждого выбранного осциллятора;
- цвет закрепляется за исходным индексом осциллятора и не меняется
  при фильтрации;
- легенда содержит исходные номера осцилляторов;
- размер SVG учитывает высоту легенды;
- по умолчанию используется 500 интервалов дискретизации на кривую;
- SVG автономен: без скриптов, внешних шрифтов, изображений и стилей.

## 6. Web API как потребитель модуля

Добавляется единый эндпоинт:

```http
POST /api/visualizations/frequency-envelopes
Content-Type: application/json
```

Тело запроса:

```json
{
  "patch": {
    "oscillators": [
      {
        "osc": {
          "freqBase": 440,
          "freqStart": 880,
          "duration": 0.5,
          "slope": 0.8,
          "phase": 0,
          "on": true
        },
        "ampEnv": {
          "startLevel": 0.5,
          "endLevel": 0.001,
          "duration": 0.5,
          "slope": 0.8
        }
      }
    ]
  },
  "oscillatorIndices": [0]
}
```

Поле `oscillatorIndices` необязательно.

Успешный ответ:

```http
200 OK
Content-Type: image/svg+xml; charset=utf-8
Content-Disposition: inline
```

Особенности:

- SVG генерируется в памяти по запросу;
- артефакт не сохраняется в `jobs/`;
- отдельный job-эндпоинт не нужен: интерфейс результата уже получает
  `job.synthConfig` и отправляет его в общий эндпоинт;
- ошибки формата патча и выбора возвращают `400` с
  `{ "error": "..." }`;
- неожиданные внутренние ошибки возвращают `500`.

Проверяются структура полного `ArgCreateSynth`, количество
осцилляторов до 50, обязательные поля, конечность чисел и существующие
диапазоны параметров. Неизвестные дополнительные поля не отклоняются.

## 7. Пользовательский интерфейс

### 7.1. Отдельная секция Visualize

Добавляется новая FSD-фича:

```text
web/src/features/patch-visualizer/
├── api/
├── model/
└── ui/
```

Секция содержит:

1. Загрузку `.json`-файла.
2. Отображение имени загруженного патча.
3. Список активных осцилляторов с чекбоксами.
4. Для каждого осциллятора — номер и основные параметры частотной
   огибающей.
5. Действия `Select all` и `Clear`.
6. Кнопку `Render`.
7. Область предпросмотра SVG.
8. Кнопку `Download SVG`.

После загрузки патча по умолчанию выбраны все активные осцилляторы.
Изменение чекбоксов применяется кнопкой `Render`, чтобы не отправлять
запрос на каждый клик.

Предпросмотр выполняется через `<img>` и object URL, без вставки SVG
через `dangerouslySetInnerHTML`. Скачивается тот же SVG Blob, который
показан в предпросмотре, поэтому скачанный рендер всегда соответствует
выбранным огибающим.

Имя файла:

```text
<имя-патча>_frequency-envelopes.svg
```

### 7.2. Результаты мэтчинга

Для завершённого задания с `synthConfig` рядом с `Download WAV` и
`Download JSON` появляется действие `Visualize frequency envelopes`.

Действие:

- передаёт существующий `job.synthConfig` в секцию `Visualize`;
- не скачивает и не изменяет WAV;
- не перезапускает оптимизацию;
- прокручивает интерфейс к визуализации;
- использует имя задания как базовое имя скачиваемого SVG.

Связь между `wav-matcher` и `patch-visualizer` организуется через
композицию в `App.tsx`, без импорта одной фичи из другой.

## 9. Проверка

Промежуточные прогоны тестов и сборок выполняться не будут. После
завершения всех подзадач реализации выполняется один финальный
комплекс:

- unit-тесты формулы, выбора осцилляторов, ошибок и
  детерминированности SVG;
- `npm run prettier:check`;
- `npm run lint`;
- `npm test`;
- `npm run build`;
- `npm --prefix web run build`;
- локальный HTTP smoke-test: запрос патча, проверка
  `image/svg+xml` и содержимого SVG.

A/B-прогоны оптимизации не требуются, поскольку оптимизатор и
вычисления синтеза не меняются.

## 10. Критерии приёмки

1. Независимый модуль принимает валидный `ArgCreateSynth` и возвращает
   SVG-строку без побочных эффектов.
2. Математика кривых совпадает с частотной огибающей синтезатора,
   включая clamp после `duration`.
3. Пользователь может выбрать подмножество активных осцилляторов, и
   только оно попадает в предпросмотр и скачиваемый SVG.
4. Завершённое задание визуализируется из сохранённого `synthConfig`
   без повторного мэтчинга.
5. Произвольный JSON-патч того же контракта можно загрузить через
   отдельную секцию `Visualize`.
6. Невалидные JSON, патч и выбор осцилляторов дают понятную ошибку и
   не приводят к сохранению артефактов.
7. Существующие скачивание WAV, скачивание JSON и поведение
   оптимизатора не изменяются.
8. Все проверки выполнены одним финальным прогоном после реализации.

## 11. Вне области задачи

- огибающие амплитуды;
- отдельный npm-пакет;
- постоянное хранение SVG;
- интерактивность внутри самого SVG;
- изменение контракта патчей;
- изменение оптимизатора или звучания;
- деплой на удалённый сервер без отдельного запроса.
